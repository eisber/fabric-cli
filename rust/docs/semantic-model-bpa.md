# Optional semantic-model BPA

This slice ports the model BPA rules from
[`semantic-link-labs@2ddf46109c1209ceffa88149f4631e7b2275f9a1`](
https://github.com/microsoft/semantic-link-labs/tree/2ddf46109c1209ceffa88149f4631e7b2275f9a1).
The inventory contains 64 rules and 87 rule/scope pairs. It is not the smaller
Fabio heuristic analyzer and does not call a backend "run BPA" endpoint.

The initial execution input is an explicit, local `model.bim` database snapshot.
Analysis never uploads, applies, refreshes, changes ownership, fixes a model,
or discovers credentials. Remote model paths and TMDL loading fail explicitly
in this slice. Generation, autofix and online evidence acquisition are separate
work; no support is implied by the optional .NET runtime.

## Crate and feature boundaries

| Crate | Responsibility | Default runtime requirements |
|---|---|---|
| `fabric-sdk-semantic-model` | Native request, report, coverage and strictness contracts; caller-injected backend | Rust only |
| `fabric-cli-semantic-model` | Arguments, local-input interface and JSON report presentation | Rust only |
| `fabric-semantic-model-dotnet` | Isolated in-process hostfxr/TOM boundary and managed BPA | Excluded from default members/consumer graph |

`fabric-sdk::semantic_model` reexports the same SDK contract. Opt into the
SDK facade's `semantic-model-dotnet` feature, or the focused SDK crate's
`dotnet` feature, only when managed execution is needed.

The existing `fab-rs` binary preserves its default command surface. Its
`semantic-model` feature registers the bounded artifact facade without .NET;
execution then reports `UnsupportedCapability` before opening input.
`semantic-model-dotnet` additionally compiles the managed component and binding:

```text
cargo build --locked -p fabric-cli --features semantic-model-dotnet
fab-rs artifact semantic-model analyze --input model.bim --hostfxr <absolute-library>
```

`--hostfxr` selects trusted executable code, not a path read from model data.
For a deployed installation, provide `--managed-component <absolute-directory>`
containing the full managed publish output. Without that option, the preview
uses Cargo's build output, which is a development convenience, not a portable
installation. The feature-on build requires the pinned .NET SDK and public
TOM package described in the binding crate README.

Only explicit `--output_format json` is supported for this preview; omission
also emits JSON without reading global CLI settings. `--input` and a remote
path are distinct authorities and conflict. `--fix` fails before input/runtime
work, rather than silently performing a read-only scan.
Direct BPA invocations also bypass automatic-update startup and navigation
restoration, including builds that opt into `self-update`.

## Inputs and result evidence

The input must be a standalone BIM database object, not a TMSL
`createOrReplace`, `alter`, `delete` or refresh script. TOM performs native
model validation; the Rust JSON-envelope check does not validate DAX or M.

Supply `--evidence <file.json>` only for explicit, previously acquired rule
inputs. Its schema is documented in
[`managed/Bpa/README.md`](
../capabilities/semantic-model/fabric-semantic-model-dotnet/managed/Bpa/README.md).
Dependency graphs, row counts, Direct Lake fallback and V-Order inspections
are not inferred from missing fields or collected automatically.
`--extended` and `--without-dependencies` do not authorize any live work.
Known-empty provider rows differ from unavailable evidence.

The JSON report includes the pinned source identity, findings, all 64 per-rule
outcomes, and matching coverage counts. Findings preserve Labs category,
rule name, severity, object type/name, description and URL. A rule with some
successful object findings can still be unavailable or failed for another
object; those findings are retained alongside incomplete coverage.

The SDK validates the complete pinned ID/name set, not just 64 arbitrary
entries or a matching count. The production identity catalog is generated by
`python -B scripts/generate_bpa_rule_catalog.py` from hash-verified inert
upstream syntax; `--check` verifies it without changing captured expectations.
Finding severity, category and object scope must also match the pinned rule.
An inconsistent producer cannot downgrade a finding to bypass strict policy.
Supplied object-level counts and issue statuses are also checked against each
rule and the aggregate outcome. Failed or unavailable object evidence cannot
accompany a completed rule or scan; aggregate object counts must agree with the
available per-rule counts. Optional metadata and unknown detail remain intact,
and an unavailable empty model does not acquire invented object counts.

`--severity info|warning|error` filters displayed findings, not rule evidence.
`--strict` adds a findings gate to complete scans; it never converts incomplete
analysis into success:

| Exit | Meaning |
|---|---|
| 0 | All rules evaluated and the selected findings policy passed |
| 1 | Unavailable/failed rules, runtime/input I/O failure, cancellation or unsupported capability |
| 2 | Invalid command or local-input contract |
| 3 | Complete scan with findings meeting the strict threshold |

An empty model is explicitly not applicable: it does not produce a clean
zero-rule report. Missing evidence cannot be replaced with invented zeros or
empty dependency lists. The rule port documents intentional fail-explicit
differences from upstream helpers that suppress source-inspection errors.

## Lifecycle and safety limits

The binding loads .NET in-process through `hostfxr`. It does not launch a Python,
CLI or managed subprocess during analysis. All hosting unsafety stays in its
private interop module; SDK/CLI and existing crates retain `unsafe_code=forbid`.
The runtime/component pair is retained for process lifetime, and calls serialize
across handles. This is not a sandbox for untrusted executable components.

Serialized requests and responses are each bounded to 16 MiB. The SDK and CLI
keep model contents out of diagnostics. Cancellation is cooperative at safe
boundaries: an in-flight TOM call finishes before cancellation returns. No hard
deadline, forced runtime unload or interrupted-call guarantee is claimed.
The native binary does not yet expose an interruptible analysis host.

## Validation scope

The independent developer oracle lives in
[`tests/compatibility/semantic_model_bpa`](
../tests/compatibility/semantic_model_bpa/README.md). It executes verified,
original upstream expressions against synthetic collaborators; it is not a
Python product dependency or a substitute for TOM/native tests.
Its seven BIM fixtures were originally captured with CRLF bytes. Scoped Git
checkout attributes preserve those exact captured bytes on every platform;
the capture manifest and its hashes are not regenerated.

Native validation must include the managed 64-rule test runner, managed ABI
boundary tests, actual Rust hosting/repeated-call tests, SDK/CLI consumers,
default feature graph exclusion and workspace architecture contracts.
Feature-on restore uses the explicit public-only `rust/NuGet.Config`; managed
packages must be locked after actual provider restoration.

Passing offline tests does not establish live XMLA, permissions, native
authentication, data-source inspection or cross-platform acceptance. Preserve
the repository's serialized shared-host build-slot and integration-custody gates.

The impact catalogue includes portable argument-only checks and a Windows-only
managed profile. CI installs the explicit .NET 8 host for that profile; the
dedicated optional BPA workflow additionally runs the managed rule/ABI runners
and actual CLI report checks. Ordinary builds still do not select .NET.

### Recorded local acceptance

Windows x64 validation on November 7, 2026 used Rust 1.99.1, the .NET 8 SDK,
and TOM 19.118.3. The managed suite passed 347 assertions; managed ABI tests
and real in-process Rust/TOM tests passed. Hosted CLI tests exercised complete
64-rule reports, strict findings, unavailable evidence, remote-target rejection
and feature isolation. The affected SDK, adapter, binding and CLI targets passed
all-target Clippy with warnings denied.

This machine could not reach the public NuGet v3 service. Local managed builds
used locked, previously restored official packages, with online vulnerability
lookup disabled only in the local validation wrapper. Repository builds and CI
retain their normal NuGet audit settings. These results are not a package
vulnerability audit or a Linux/macOS runtime acceptance claim.
